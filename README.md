# qaravan-forms

Публичная витрина форм обратной связи QARAVAN. Здесь живёт только код формы — вся остальная автоматика в приватном репозитории `qaravannyc/events-robot`.

## Почему отдельный публичный репозиторий

Vercel на плане Hobby не деплоит приватные репозитории организации (для этого нужен Pro). Поэтому папка `form/` вынесена сюда, в публичный репозиторий, а робот, выгрузки Partiful и рабочие заметки остались приватными.

## Маршруты

- `/<monday-item-id>` — форма отзыва для гостя
- `/<monday-item-id>/lead` — форма для волонтёра-ведущего
- `/feedback/<monday-item-id>` и `/feedback/<monday-item-id>/lead` — те же формы, старый вид ссылки
- `/survey` — исследование потребностей сообщества 2026 (папка `survey/`, отправка через `api/survey.mjs`)
- `/letter` — анкета на письмо поддержки для иммиграционного дела (папка `letter/`, приём через `api/letter.mjs`)
- `/event-volunteers` — запись волонтёров событий на роли организаторов по месяцам (папка `event-volunteers/`, приём через `/api/event-volunteers`). Это не общая запись волонтёров — та живёт на qaravan.org/volunteer
- `/support/gina` и `/support/simon` — анкеты групп поддержки: группа поддержки с Джиной и группа равной поддержки с Саймоном (папка `support/`, приём через `/api/support-groups`)
- `/support/send?t=…` — страница, с которой ведущая группы поддержки отправляет участникам ссылку на встречу (приём через `/api/meetings`; ссылку на страницу присылает письмо накануне встречи)
- `/support/attendance?t=…` — страница, на которой ведущая после встречи отмечает, кто пришёл (приём через `/api/attendance`; ссылку присылает письмо сразу после встречи)
- `/support/status?t=…` — статус анкеты группы Джины (New, Contacted, …) по кнопке «Изменить статус» из письма команде о новой анкете (приём через `/api/status`)
- `/api/agreement-invite` — не страница: вебхук monday, приглашение подписать Соглашение сообщества новому волонтёру (ниже)
- `/api/website-inquiry` — не страница: вебхук monday, письмо команде о новом обращении через форму на qaravan.org (ниже)
- `/api/team-email` — не страница: вебхук monday, письмо команде о новой записи в волонтёры, заявке на роль или в Rainbow Connections (ниже)

ID в ссылке — это id строки события на доске Event Calendar в monday.

## Опрос потребностей 2026 (`/survey`)

Анонимный опрос из 24 вопросов на шести языках — русский, английский,
украинский, грузинский, узбекский (латиница), казахский; выбор языка —
выпадающим списком в шапке, язык заполнения пишется в колонку Language. Ответы
ложатся на приватную доску monday
**Community Needs Survey 2026** (id `18426996689`): черновики автосохраняются в
группу In progress после каждого ответа, отправленные ответы переезжают в
Submitted. Один респондент — одна строка; браузер держит случайный response id
в localStorage, поэтому человек может прерваться и продолжить на том же
устройстве, а по личной ссылке `/survey?r=<response-id>` («Продолжить на другом
устройстве» внизу каждого раздела) — и на любом другом: GET `/api/survey?rid=`
отдаёт черновик с доски. Имён, почт и телефонов форма не собирает.

На версиях, переведённых с помощью ИИ (все, кроме русской и английской), внизу
каждого раздела есть тихая кнопка «Заметили ошибку в переводе?» — репорты
уходят на доску **Survey Translation Reports** (id `18427148568`): язык версии,
раздел и текст замечания, статус New → Fixed/Dismissed. Репорты анонимны и не
связаны с ответами на опрос. Структура данных и коды — в `survey/CODEBOOK.md`.

### Аналитика опроса

`tools/aggregate-survey.mjs` читает JSON из «⚙️ Raw answers» (источник истины —
машинные коды, а не переименовываемые метки), применяет правила баз (роутинговые
пропуски вне базы, «предпочитаю не отвечать» отдельной строкой, эксклюзивные
варианты вне числителей, подгруппы с базой < 10 подавляются) и переписывает
доску **Survey 2026 — Aggregates** (id `18427179045`): одна строка = один
столбик одного вывода, вкладки-представления по каждому анализу, журнал
прогонов в группе Run log. Группу A7 (темы открытых ответов, кодируются руками)
скрипт не трогает. Дашборд **QARAVAN Needs Survey 2026** (id `38957850`)
совмещает живые виджеты по доске ответов и посчитанные проценты с агрегатов.

Запуск: еженедельно по понедельникам Vercel-кроном через `/api/aggregate` —
для этого в переменных окружения Vercel должен быть задан `CRON_SECRET`
(без него эндпоинт отказывает). Вручную: `MONDAY_TOKEN=… node
tools/aggregate-survey.mjs` или GET `/api/aggregate?key=<CRON_SECRET>`.

## Анкета на письмо поддержки (`/letter`)

Форма для участников сообщества, которым нужно письмо-декларация от QARAVAN
для иммиграционного дела: `feedback.qaravan.org/letter`. 19 вопросов в четырёх
разделах (по решению команды форма не спрашивает A-number, не просит личную
историю / personal statement и не собирает документы; вместо даты рождения —
возраст; последний вопрос — открытый «Что-то ещё?» до 1000 знаков), по одному вопросу на экран, шесть языков (по умолчанию английский;
переключатель — в шапке). Дизайн и тексты — из прототипа Claude Design
«Letter Intake Form» (папка `letter/`, спецификация — в описании коммита и в
комментариях к файлам).

- `letter/index.html` + `letter/app.js` — сама анкета (без фреймворков).
  Тексты всех шести языков — `letter/strings.js`; названия событий —
  `letter/intake-events.js` (английский источник, идентификаторы позиционные,
  **не переставлять**) и `letter/events-i18n.js` (переводы по id); страны —
  `letter/countries.js` (ISO-коды, имена локализует браузер); невидимые синонимы
  для поиска по событиям («хайк» → hike/поход, «пати» → party) —
  `letter/search-synonyms.js`, группы слов-основ, дописывать можно свободно.
- `api/letter.mjs` — автосохранение после каждого ответа (`mode: draft`),
  отправка (`submit`), выдача черновика по личной ссылке (`GET ?rid=`) и
  сообщения об ошибках перевода (`mode: feedback`). Всё в одной функции: на плане
  Hobby Vercel не собирает деплой больше чем с 12 функциями в `api/`. Общий код и
  карта колонок — `lib/letter-board.mjs`, письма — `lib/letter-mail.mjs`.
- Ответы ложатся на приватную доску monday **Letters of Support — Immigration
  Cases** (id `18429448469`): черновики — в группу «Form — started, not
  finished» (Form status = In progress), отправленные — в «Form — answers
  received» (Letter Status = Answers received) плюс апдейт с полным читаемым
  текстом ответов. Колонок немного: Form status и Form progress (на каком
  вопросе, сколько минут, язык), Age, Proceeding, Identities & experiences, Roles at QARAVAN,
  Attorney email, Key events at home, Other support letters, References at
  QARAVAN, Partner, Consents given, Anything else, Translation feedback (что
  написали в «Заметили ошибку в переводе?» внизу любого шага); всё про
  участие (частота, первый контакт, события, вклад) собирается в существующую
  Involvement Summary. Каждый ответ — одна строка; ключ — «⚙️ Intake id» (UUID,
  который придумывает браузер). «⚙️ Raw answers» — JSON для личной ссылки,
  «⚙️ Path log» — путь по анкете (шаги, время, направление: next / back / jump /
  peek / skip / error / submit…) — по нему видно, кто дошёл до последнего шага
  и где бросил.
- Личная ссылка `/letter?r=<intake id>` открывает тот же черновик на любом
  устройстве; она уходит письмом на почту сразу после шага «Как с вами
  связаться» (Gmail API, те же `GOOGLE_*`, что и для фото — в токене должен
  быть scope `gmail.send`; без него форма работает, а ссылку показывает на
  экране). После отправки — письмо-подтверждение. Команде при первой отправке —
  письмо о новой заявке (`teamEmail` в `api/letter.mjs`, кому — как в
  `/api/team-email` ниже): дело, срок, контакты, кто знает человека и Context;
  идентичности и события на родине в письмо не идут, они на доске. Его раньше слала
  автоматизация monday на доске (Form status → Submitted); она выключена.
- Локально: `node tools/letter-dev.mjs` — сервер на :3999 с поддельным monday
  (ничего никуда не пишет), удобно прокликать анкету целиком.

## Запись волонтёров событий (`/event-volunteers`)

Анкета «Стать волонтёром событий QARAVAN» — для команды, которая придумывает и ведёт события (не путать с общей записью волонтёров на qaravan.org/volunteer, куда пишутся все; анкета сама отсылает туда тех, кто хочет помогать иначе): `feedback.qaravan.org/event-volunteers`. Одна
страница, RU/EN: имя, местоимения, Telegram, Instagram, телефон и почта
(обязательны), шесть ролей карточками с описанием и часами, месяцы, как часто,
был(а) ли на событиях, комментарий. Черновик держится в localStorage до отправки.
Ссылка с `?role=maker` (или `?role=maker,keeper`) сразу отмечает роль — удобно
для постов «ищем Maker»; `?lang=en` открывает английскую версию.

- Месяцы продлеваются сами: анкета предлагает `MONTHS_AHEAD` (6) месяцев начиная
  со следующего. Метку нового месяца («Апрель 2027») на доске сервер создаёт сам
  при первой заявке (`create_labels_if_missing`). Представление «Команда: …» и
  график в «Сводке» для нового месяца на доске добавляются вручную.
- Приём — `lib/event-volunteers.mjs`. Своей функции нет (лимит 12 функций на Hobby):
  `vercel.json` переписывает `/api/event-volunteers` на `/api/survey?form=event-volunteers`,
  и `api/survey.mjs` первой строкой отдаёт такой запрос в `lib/event-volunteers.mjs`.
- Заявки ложатся на приватную доску monday **Волонтёры событий — запись на роли**
  (id `18432838181`), группа «Заявки»: одна заявка — одна строка со статусом
  «Новая», плюс апдейт с полным текстом ответов. Колонки и метки этой доски
  названы по-русски по просьбе команды — исключение из правила выше; метки в
  `lib/event-volunteers.mjs` должны совпадать с доской символ в символ. Уведомление
  о новой заявке и напоминания — автоматизации самой доски.
- Локально: `node tools/event-volunteers-dev.mjs` — сервер на :3998 с поддельным
  monday, `/__db` показывает, что ушло бы на доску. Проверки:
  `node --test tools/event-volunteers.test.mjs`.

## Анкеты групп поддержки (`/support/gina`, `/support/simon`)

После отправки — «Спасибо» и кнопка в Telegram-сообщество Qaravan Connects (https://t.me/+oKO-rkUI2oU2OTUy).

  `support/app.js` (`FORMS` и `TEXTS`), стили — `support/support.css`.

  и `api/survey.mjs` отдаёт такой запрос туда.
- Джина: приватная доска monday **Support Group with Gina — Sign-ups**
  (id `18433061986`), новые анкеты — в группу «New sign-ups» со статусом New.

- Вопрос «Что вам сейчас нужнее всего?» (у Джины): до трёх вариантов в порядке

  Typeform «три главные потребности»: 82 ответа людей, живущих в США (ответы из-за

- Перед письмом анкета смотрит, что о человеке уже есть в monday (`lib/person-lookup.mjs`,

- Локально: `node tools/support-groups-dev.mjs` — сервер на :3997 с поддельным

## Статус анкеты по кнопке из письма (`/support/status`)

В письме команде о новой анкете в группу Джины кнопка «Изменить статус» открывает
`/support/status?t=<ключ>` (`lib/status.mjs`, `support/status.html`, `support/status.js`):
имя, почта, дата анкеты и статусы из колонки Status доски группы — те же, что в monday,
в том же порядке (читаются с доски: новый статус в monday появится и здесь, выключенные
не показываются), с пояснением по-русски. «Сохранить статус» записывает выбранный в
monday и оставляет на строке апдейт «Статус: New → Joined». С «Joined» человек начинает
получать письма со ссылкой на встречу. Ключ — тот же HMAC, что у страниц встречи, с
назначением `k: "st"`, на эту строку и группу, работает год. Для анкет, пришедших до
этой кнопки: `/api/status?key=<CRON_SECRET>&item=<id строки>` отдаёт ссылку на страницу.
Проверки: `node --test tools/status.test.mjs`; локально — `node tools/meetings-dev.mjs`.

## Письмо со ссылкой на встречу (`/support/send`)

Джина и Саймон рассылают ссылку на встречу одной кнопкой и без входа в monday
(`lib/meetings.mjs`, `support/send.html`, `support/send.js`).

- **Накануне, с 8 до 9 вечера по Нью-Йорку.** `/api/meeting-prompts` зовут крон воркера
  Cloudflare раз в 5 минут (`events-robot/telegram/worker.mjs`, `pokeForms`), Vercel-кроны в
  00:00 и 01:00 UTC (`vercel.json`; на Hobby — в течение своего часа: летом 00 UTC — это 20:00 в
  Нью-Йорке, зимой — 01 UTC) и, для подстраховки, GitHub Actions. Письмо уходит при первом
  запуске, когда накануне встречи в Нью-Йорке уже 20:00 или позже (раньше — никогда); если

  ведущей и команде группы (`team` в `GROUPS`: у Джины — Глеб и Анна) — одновременно, каждому

- **Отправка.** Одно письмо: ведущей в «Кому», всем выбранным — в скрытой копии, ответы

  команды; страница показывает, кто и когда уже отправил, и повторная отправка — только

## Кто пришёл на встречу (`/support/attendance`)

После встречи группы поддержки ведущая отмечает, кто на ней был, а отметки попадают в
«Confirmed attendees» этой встречи в календаре событий (`lib/attendance.mjs`,
`support/attendance.html`, `support/attendance.js`; письмо — `askAttendance` в
`lib/meetings.mjs`).

- **Письмо сразу после встречи.** Раз в 5 минут `/api/meeting-attendance` зовёт крон воркера
  Cloudflare (`events-robot/telegram/worker.mjs`, `pokeForms`; Cloudflare запускает его
  каждую минуту, надёжно), для подстраховки — GitHub Actions
  (`.github/workflows/meeting-attendance.yml`; его расписание ненадёжно, а чтобы GitHub не
  отключил его после 60 дней без изменений, `.github/workflows/keepalive.yml` раз в месяц
  заново включает его через API). Письмо уходит в первые 5 минут после конца встречи —
  ведущей и команде группы, каждому со своей кнопкой. Для встреч Джины и Саймона, которые закончились
  за последние 12 часов (конец — начало плюс `minutes` из `GROUPS`, а если там 0 — 90
  минут), ведущей уходит письмо «Встреча 30 сентября: отметьте, кто пришёл» с кнопкой.
  Один раз на встречу (отметка `attendanceAsked` в «⚙️ Meeting email»), «Cancelled»
  пропускается. Обычный прогон открыт без секрета: он пишет только ведущим и отвечает без
  ссылок и адресов.
- **Страница.** По кнопке — компактная сетка (`support/roster.js`, стили `.roster` в
  `support/support.css`; так же и на странице отправки ссылки): сверху участники группы
  (у Джины — «Joined», у Саймона — галочка рассылки) по имени, под ними новые анкеты
  (New, с оранжевой меткой) и уже отмеченные на этой встрече; остальные анкеты и бывшие на
  прошлых встречах — в свёрнутом разделе «Остальные анкеты» (открывается нажатием, а при
  поиске — сам). На телефоне в открытых разделах только имена, чтобы группа помещалась
  примерно на один экран. Список не двигается от галочек: разделы и порядок задаются при
  загрузке, добавленные вручную — в конце. Поиск, «Добавить человека» (имя и почта),
  отметки держатся в localStorage до сохранения. Ссылка работает две недели после
  встречи, до начала встречи не открывается; сохранять можно сколько угодно раз.
- **Сохранение.** Отмеченные — карточки доски посетителей мероприятий (18425190164):
  у кого карточки ещё нет, ищем по Email, потом по «Other emails», а не нашли — заводим
  (имя, почта, First seen — день встречи, Sources «support group attendance», группа
  People). Снятая галочка убирает человека из «Confirmed attendees»; кого добавили в
  monday вручную, пока страница была открыта, не трогаем; отмеченных убираем из «Did not
  attend / declined» этой встречи. «Guest records» (регистрации) не трогаем. На строке
  встречи — отметка `attendance` в «⚙️ Meeting email» и апдейт без имён и адресов.
- **Зачем.** Годовые доски посещений (`sync-attendance` в events-robot) считают
  «Confirmed attendees» подтверждённым участием, а раздел «Контекст» в письме о новой
  анкете показывает эти встречи. Робот events-robot сам эти колонки у групп поддержки не
  пишет: у них нет ссылки на Partiful.
- **Ключ** — тот же HMAC, что у `/support/send`, с пометкой назначения (`k: "att"`):
  ключ одной страницы другую не открывает.
- **Вручную** (нужен `CRON_SECRET`): `/api/meeting-attendance?key=<CRON_SECRET>&item=<id
  строки>` — письмо ведущей по этой встрече сейчас, даже если уже спрашивали; `&to=<почта>`
  вместе с `item` — тестовая копия на другой адрес (встреча не помечается): страница
  настоящая, но «Сохранить» ничего не записывает в monday; `&dry=1` — ничего не отправлять,
  показать ссылки.
- **Отмечают вместе.** У каждого из команды своя кнопка. Отметки складываются: снимается
  только та галочка, которую человек снял сам, чужие отметки не пропадают, даже если
  страницы были открыты одновременно. Кто открывает вторым и третьим, видит «Уже отмечали:
  Джина — …, 7 человек» и галочки как сохранено сейчас; если за время, пока страница была
  открыта, сохранил кто-то ещё, после сохранения страница скажет об этом и покажет общий
  список. Журнал сохранений — `attendanceLog` в «⚙️ Meeting email», апдейт — с именем.

## Безопасность и надёжность

- **Ключи в ссылках** — HMAC-SHA256 (секрет `MEETINGS_SECRET` или производный от
  `MONDAY_TOKEN`), сравнение за постоянное время; в ключе — строка, группа, срок и
  назначение (`k`): отправка ссылки — до 6 часов после начала встречи, «Кто пришёл» — две
  недели, статус анкеты (`k: "st"`) — год. Ключ одной страницы другую не открывает.
  Тестовые копии (`&to=`) несут в ключе адрес проверяющего (`r`): с их страниц участникам
  ничего не уходит и в monday ничего не пишется.
- **Письма участникам** — одним письмом, все в скрытой копии; адреса в заголовки попадают
  только простые (`ADDR_RX` в `lib/meetings.mjs`: без запятых, скобок, пробелов и переводов
  строки). В апдейтах на строках календаря — без имён и адресов (апдейты этой доски
  пересылаются в Slack, если там подключена автоматизация).
- **Страницы ведущей** (`/support/send`, `/support/attendance`, `/support/status`) — без
  индексации, без Referer, не встраиваются в чужие страницы (`X-Frame-Options: DENY`) и не
  кешируются; данные — только через `/api/*` с `Cache-Control: no-store`; весь текст
  вставляется как текст (`textContent`), в письмах — с экранированием.
- **Ручные режимы** — только с `CRON_SECRET`. Секрет однажды пересылали в чате, поэтому его
  стоит сменить в Vercel.
- **Запуски по времени.** Основной — крон воркера Cloudflare (telegram-бот в events-robot)
  раз в 5 минут зовёт `/api/meeting-attendance` и `/api/meeting-prompts`; Vercel-кроны
  (раз в сутки, в течение часа) — второй путь для вечернего письма; GitHub Actions —
  третий. Эндпоинты идемпотентны: лишний запуск ничего не задвоит.

## Приглашение подписать Соглашение сообщества (`/api/agreement-invite`)

Волонтёрская роль начинается с подписанного Соглашения сообщества. Кто записался в
волонтёры любой формой и не подписал его, получает от info@qaravan.org письмо с
личной ссылкой на форму соглашения — через минуту-другую после записи.

- **Кто зовёт.** На каждой доске волонтёрских форм — Volunteer sign-ups, «Волонтёры
  событий» (`/event-volunteers`), Event Project Manager, Community Manager — вебхук
  monday (мутация API `create_webhook`, событие `create_item`) на
  `https://feedback.qaravan.org/api/agreement-invite`. Он приходит в момент появления
  строки с телом `{"event": {"boardId": …, "pulseId": …}}`; при подключении monday
  присылает `{"challenge": …}`, эндпоинт отвечает им же. Общая форма ещё и сразу
  переводит человека на соглашение: кто подпишет там сразу, получит и письмо, а
  робот потом отметит приглашение «Signed», и напоминаний не будет. Вебхуки видно
  запросом `{ webhooks(board_id: …) { id event config } }`.
- **Что решает.** Строка должна быть с одной из этих досок, не раньше 28 сентября
  2026 (START) и не старше 14 дней. Подписи ищутся там же и теми же правилами, что у робота: доска
  Community Agreement (по коду из личной ссылки, почте, карточке человека или полному
  имени), «Agreement signed» в Community Members, отметки старых форм. У кого на доске
  **Community Agreement invites** уже есть строка (по почте или полному имени), тому
  второго письма нет. Отписавшимся, общим ящикам и строкам «Test» не пишем.
- **Сначала строка, потом письмо.** Строка приглашения пишется до письма; если monday
  позвал дважды, письмо шлёт тот вызов, чья строка первая, второй её удаляет. Письмо
  не ушло — строка «Send failed», ответ 502 (в логах Vercel).
- **Остальное — робот** (events-robot, `robot/agreement-invites.mjs`): напоминания раз
  в неделю, до четырёх; отметка «Signed», когда человек подписал; и всё, что вебхук
  пропустил, — с часа после записи.
- **Один код на двоих.** `lib/agreement.mjs` (правила), `lib/agreement-email.mjs`
  (письмо по дизайн-системе, английский сверху, русский снизу) и `lib/wordmark-email.mjs`
  (логотип внутри письма) — копии файлов робота из `events-robot/robot/lib/` один в
  один: меняются вместе.
- В ответе нет имён и адресов: `{"result": "sent" | "skipped", "why": …}`. `?dry=1`
  (можно GET: `/api/agreement-invite?dry=1&item=<id строки>`) — сказать, что было бы,
  без записи и письма. Проверки: `node --test tools/agreement-invite.test.mjs`.

## Письмо о новом обращении с сайта (`/api/website-inquiry`)

Форма на qaravan.org пишет строку на доску **Website submissions** (id `4939299706`):
имя в названии строки, фамилия, местоимения, категория, текст, почта, телефон, город.
Об этой строке команде приходит письмо от info@qaravan.org, свёрстанное как письмо об
анкете группы поддержки (`lib/support-mail.mjs`), но по-английски (так решил владелец):
категория с флажком её цвета, имя, кнопка Reply, текст обращения с его переносами
строк, контакты и Context — что о человеке уже есть в monday (данные
`lib/person-lookup.mjs`, английские строки — `contextRows` в `lib/website-inquiry.mjs`,
плюс прежние обращения с той же почты). Тема у каждого письма своя («Website inquiry:
имя, категория»), поэтому Gmail не склеивает разные обращения в одну цепочку.

- **Кто зовёт.** Вебхук monday на доске (`create_webhook`, событие `create_item`) на
  `https://feedback.qaravan.org/api/website-inquiry`; challenge — как у Соглашения выше.
  Раньше письмо слала автоматизация monday на доске («When a new item is created, send
  an email»); её выключают в Automate на доске, иначе письма приходят дважды.
- **Кому.** `NOTIFY` в `lib/website-inquiry.mjs` (ezra@qaravan.org); переменная
  `WEBSITE_NOTIFY` в Vercel, адреса через запятую, его заменяет.
- **Один раз.** Строка не старше суток; после письма на строку ложится апдейт «Team
  email sent…» с разделом Context, и повтор вебхука второго письма не шлёт (прежняя
  русская пометка «Письмо команде отправлено» тоже считается). Письмо не ушло — ответ
  502, monday позовёт ещё раз.
- **Ответить.** Кнопка открывает новое письмо на адрес человека (тема по-русски, если
  он писал кириллицей). Обычный «Ответить» в почте ушёл бы на info@qaravan.org; Reply-To
  на человека не ставим, иначе ему ушла бы цитата этого письма вместе с Context.
- Всё из формы экранируется. В ответе эндпоинта нет имён и адресов; `?dry=1` — сказать,
  что было бы. Проверки: `node --test tools/website-inquiry.test.mjs`.

## Дизайн

Все формы (отзыв гостя и ведущего, несколько событий, фото, опрос, анкета на
письмо, анкеты групп поддержки) и страницы после ссылок из писем (отписка, «меня там не было») собраны
по дизайн-системе QARAVAN, ревизия 2026-09: Fira Sans для текста и Fira Sans
Condensed для заголовков, кнопок и подписей; белая страница, квадратные формы,
шесть цветов бренда только флажками и метками, без тонированных подложек.

- `assets/qaravan.css` — шрифты, токены (значения из `tokens.json` дизайн-системы)
  и базовые правила. Подключается первым на каждой странице.
- `assets/forms.css` — общие компоненты форм отзыва и опроса: переключатель
  RU/EN, звёзды, варианты ответа, поля, кнопки, сообщения об ошибке, блок
  доната, загрузка фото. В `<style>` страниц остаётся только своё.
- `assets/fonts/` — файлы шрифтов из дизайн-системы (кириллица, украинский,
  казахский, узбекский; грузинский — FiraGO), лицензия OFL рядом.
- `assets/logo-wordmark.svg` — логотип: официальные контуры, не живой шрифт.

Анкета `/letter` берёт только `qaravan.css`: у неё свои компоненты в
`letter/index.html`.

Письма свёрстаны по тем же правилам: белая страница, колонка 560px слева, логотип —
`logo-email.png` (официальные контуры, 140px), чернила на белом, второй язык —
приглушённой строкой, квадратная чернильная кнопка, ссылки чернилами с голубым
подчёркиванием, цвет — только флажками и полосками. Почта не грузит веб-шрифты, поэтому
запасной шрифт — обычный Helvetica/Arial, без Arial Narrow. Так сделаны `lib/letter-mail.mjs`,
`lib/support-mail.mjs`, `lib/meetings.mjs`, `lib/website-inquiry.mjs`, `lib/team-email.mjs`,
`lib/agreement-email.mjs` и письма опросов в events-robot (`robot/emails.mjs`).

## Переменные окружения (задаются в Vercel, не в коде)

- `MONDAY_TOKEN` — обязательна, без неё форма не найдёт событие
- `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REFRESH_TOKEN` — загрузка фото и видео в Google Photos, письма анкеты `/letter`, приглашения подписать Соглашение и письма команде о новых анкетах и обращениях с сайта (scope `gmail.send`)
- `WEBSITE_NOTIFY` — необязательна, кому письмо о новом обращении с сайта (адреса через запятую; по умолчанию ezra@qaravan.org)
- `TEAM_NOTIFY` — необязательна, кому письма о новых записях в волонтёры, заявках на роли, в Rainbow Connections и на письмо поддержки (адреса через запятую; по умолчанию ezra@qaravan.org)
- `FORM_BASE` — необязательна, адрес формы для ссылок в письмах анкеты (по умолчанию `https://feedback.qaravan.org`)

## Правило

В этот репозиторий никогда не коммитятся токены и ключи, он публичный.

## Feedback photo uploads

The attendee, lead, photos-only, and multi-event forms accept up to 50 files per
event. The server applies the same limit. Four direct Google Photos transfers
can run at once; a separate worker prepares one image at a time so selection
and form controls stay responsive.

JPEG optimization preserves the full pixel dimensions and uses quality 0.94.
It replaces a file only when at least 10% smaller. The original-files checkbox
applies to subsequent selections and skips re-encoding. Other formats and
videos remain unchanged, and unsupported browsers fall back to the original.
Optimized JPEGs lose camera metadata such as EXIF capture dates; use originals
when that metadata or an untouched publication source is needed.

Run the upload, cancellation, 50-file, and album-failure regression checks with:

```sh
node --test tools/photo-*.test.mjs
```

Feedback copy follows [NN/G error-message guidance](https://www.nngroup.com/articles/error-message-guidelines/)
and the [GOV.UK button guidance](https://design-system.service.gov.uk/components/button/):
name the action, describe the current state, and give a concrete recovery step.
Failed selected files require retry or removal before submission. Album failures
show a warning even when an attempted backup succeeds.
